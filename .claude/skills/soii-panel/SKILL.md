# Panel

For decisions worth stress-testing. Read-only: it writes nothing unless the owner then asks you to save the outcome.

## 1. Load context

Read the notes the decision touches: the project or area note, related people, earlier decisions on the same thing (search the vault). If the vault has an "about me" or key-facts note, read it only if the owner points you to it or the decision is plainly personal; don't hunt for one.

## 2. State the decision

One sentence. If the owner hasn't given it that clearly, say it back and let them correct it. Also ask what's at stake (money, time, a relationship) if that's not in the notes.

## 3. Convene the panel

Pick three or four perspectives that fit this decision. Defaults:

- **The Operator:** the most efficient, lowest-risk, fastest path.
- **The Contrarian:** what is wrong with the obvious answer? What are you missing?
- **The Customer:** what would the end user, client or the other person actually experience?
- **The Long Game:** what does this look like in twelve months if done wrong, and if done right?
- **The Frugalist:** the cheapest version that still works.

Swap in others when they fit better (a lawyer, a friend, the person you'll be in five years). Each argues alone, from their stance only, using what the vault says where it's relevant (cite it as `[[note]]`):

```
### <Perspective>
3–5 sentences arguing the position.
**Verdict:** a specific recommendation.
```

Don't let the perspectives agree for the sake of it. If two land in the same place, say so as a finding.

## 4. Synthesize

State the tension between the perspectives. Then give one recommendation that resolves it, and name what is sacrificed by choosing it.

## 5. Offer to save

Ask whether to log the decision with `/soii-save`. Don't write anything before they say yes.
